- **明暗反了，确认是代码问题。** `Map/TerrainHeightShading.Calculate` 的亮度 ∝ `(gx + gz + 2)`，

  世界 +X 在屏幕左、+Z 在屏幕上），光照没跟着转 → 屏幕上光从**右下**来。
  人眼默认光从左上来，于是凹凸看反（截图里抬高的屋顶，暗边都在上侧和左侧）。
  `src/` 和 `plugin/` 两份 `TerrainHeightShading.cs` 逐字节相同。
- 瓦片只存明暗字节（`MapTile` 每格 1 字节，0=未知、128=中性），**不存高度**，老数据无法精确重算。

  | 公牛 | – | 0.5 | – |
  | 母牛 | 0 / 0 | 0 | 0.1 |

## 二、已确认的设计

用户 11-20 定了版本号 2.9.0。下面的规则是我上一轮给的建议，用户没有反对，按此执行；
标 ★ 的是我补的细节，用户没有逐条确认过。

### 1. 明暗

- 光改成从屏幕左上来（固定北朝上时）：世界 +X / +Z 一侧受光。
- 固定北朝上时完全正确；“朝向跟随”模式下明暗是烘在像素里的，会跟着地图转（与以前一样，不处理）★。
- 老数据：读到旧格式瓦片时，明暗字节按中性值镜像（`b' = clamp(256 − b, 1, 255)`，0 保持 0），
  并把该瓦片里有探索数据的区块标成“明暗待重录”；玩家走到附近时这个区块重录一次（沿用 2.8.0 补季节数据的办法），
  重录后标记清除。单格小坑、小尖的额外加减会被镜像反，影响小，重录后就对了。

### 2. 四色标记

态度（颜色）和体型（大小）分开：

| 颜色 | 条件（按顺序判断，先中先定） |
|---|---|
| 红 | 此刻追击目标是玩家；或已知模组敌人组件（`ComponentTacticalEnemy`、`ComponentMDRobot`，看不出是否在追，一律红） |
| 蓝 | 已知友方组件（`ComponentTacticalCompanion`）；或模板名以 `_Saddled` 结尾 |
| 黄 | 原版追击行为满足任一：主动追击范围 > 0（插件版还要 AttacksPlayer）、碰到就冲 > 0、被打还手 ≥ 0.5；或类别是捕食者 |
| 绿 | 其余 |

- 体型：会飞=鸟、水生=鱼、其余=陆地。鸟鱼按 60% 大小画★，颜色同上；“显示鸟/鱼”两个开关保留。
- 红色标记 125% 大小保留★。
- 蓝色友方此刻在追玩家的话显示红（与 2.8.0 一致）。
- 去掉 2.8.0 的鸟黄、鱼青两色。

## 五、执行记录（2026-11-20，实现时补的判断）

计划没覆盖、需要判断的地方，都选了最保守的做法：

1. **洞穴层不镜像。** 洞穴图层也用 `ExplorationTileStore` + `TileCodec`，但它的明暗字节是“相对高度系数”
   （`CaveMapSampler` 用 `Encode(HeightFactor…)`），不是光照，镜像会把高低弄反，而且洞穴的“已探索”判断不看重录掩码，
   会永远错下去。所以 `ExplorationTileStore` 加了参数 `mirrorLegacyHeightShades`（默认 true），
   `CaveExplorationStore` 传 false；洞穴瓦片照样写成 v5，掩码为 0。
2. `IsChunkShadeCurrent(x, z)` 的参数是瓦片内的**像素**坐标（和 `IsRegionFully…` 一致），落在哪个 16×16 区块就查哪一位。
   瓦片不存在、或缓存满了暂时腾不出位置时返回“已是新的”（前一个条件本来就会让区块算作未探索；后一种下次再查）。
3. `SetRegion` 清掉的是“被这次写入**完整覆盖**的区块”的位，不要求恰好一个区块；部分写入不清。
4. **插件版 AttacksPlayer** 同时作用于“主动追击范围”和“碰到就冲”两条（游戏代码里这两条都检查 AttacksPlayer），
   “被打还手”不受它影响（游戏代码不检查）。计划只写了范围一条。
5. 红色标记一律 125%，不管体型（例如正在追玩家的鲨鱼）；体型判断沿用 2.8.0 的顺序：先水生、再会飞。
6. “显示鸟类/鱼类”开关按体型判断，红色的鸟/鱼关掉开关后也不显示（照计划字面）。
7. **生物数值核对**：插件版 1.9.2.1 `Content.zip/Assets/Database.xml` 与联机版 `~/sc-src/Assets/Database.xml` 按继承链取值，
   五种生物两版完全相同；但和第一节的表不同：公牛主动追击范围是 1.5 / 1.5、被打还手 1；狼碰到就冲 1、被打还手 1
   （表里写“–”）。分类结果不受影响（狼、公牛仍是黄），测试按数据库数值写。
8. 隔离测试 `--mode markers` 里狼、公牛、鲨鱼、尸鬼的期望写成“黄或红”，因为刷出来时可能已经在追玩家。
9. **尸鬼模组的尸化头颅现在显示绿色**（2.8.0 是红色）。实测它只有 `CorpsificeHead` 等组件，没有原版追击行为，
   也不在已知敌人组件名单里，按本计划的规则就是绿。没有自作主张把它加进名单；要不要加请用户定。
10. 隔离测试发现：插件版和联机版的 `data:/` 都是 `%LOCALAPPDATA%\Survivalcraft`，和用户自己玩的游戏共用——
    旅行地图的 `settings.json` 和每个世界的地图缓存都在那里，以前的隔离测试（含 2.8.0）一直在往里写测试世界的地图。
    插件版的测试模组现在用 Harmony 把 `Engine.Storage.GetDataDirectory` 指到隔离副本里的 `isolated-data`；
    联机版没有 Harmony，没有隔离（本轮联机版只跑了 shading 和 markers 两项）。
11. 小地图会在区块一加载就记录它看得见的所有区块，所以隔离测试建好台和坑后，先用公开接口把这两个区块标成未探索，
    再让地图重新记录；旧存档测试在离场地 400 格处存档，保证重新打开时场地既没加载也不在小地图里。
